# 2.4.0 - Native Chinese calendar

Released 2026-11-14. This is an additive release with no changes to the existing calendar APIs.

## Added

- **`:calendar-chinese-native`** — dependency-free Kotlin Multiplatform engine for the Chinese
  lunisolar calendar: validating `ChineseMonth`/`ChineseDate` values, leap-month identity,
  bidirectional epoch-day conversion, month/year lengths, leap-aware navigation, bounded
  `1901..2099` data, and `jvm()` plus `linuxX64()` targets.
- **`:calendar-chinese-compose`** — optional Compose facade with `ChineseCalendarMonth`,
  `GregorianChineseCalendarMonth`, month/week data, saveable leap-aware state, heatmaps and the
  shared selection/renderer pipeline.
- **Sample and publishing integration** — Chinese playground, BOM/JitPack entries, API dumps and
  CI verification for both new modules.

## Compatibility

- Additive: the public JVM API dumps of `library`, `calendar-gregorian`, `calendar-hijri`,
  `calendar-solarHijri` and `calendar-solarHijri-native` are unchanged.
- The engine has no Android, Compose, Java date or foreign calendar dependency; the Compose
  facade remains Android because `:library` is Android-specific.
- Supported range: Chinese years `1901..2099` (Gregorian `1901-02-19..2100-02-08`).

## Verification

- 211 JVM tests (197 Android JVM + 14 KMP), 14 linuxX64 tests, sample build, API guard and
  publication/consumer checks passed.
- Verification, Publishing, Instrumentation and Tablet workflows were green on the verified
