Kotlin Multiplatform release of the calendar library.

The shared Compose core and all calendar engines now build for Android, the JVM and iOS from
`commonMain`. Public APIs use epoch days and immutable calendar value types instead of
`java.time` and `java.util.Locale`; this is a breaking major release.

Highlights:

- Gregorian, Hijri, Solar Hijri and Chinese lunisolar engines on Android, JVM and iOS.
- Dependency-free Solar Hijri and Chinese engines; `ir.huri:jalalicalendar` is gone.
- Published iOS klibs and a KLIB ABI snapshot guard alongside the JVM API dump.
- Calendar-independent Compose views, heatmaps, adaptive months, selection and saved state.
- 165 JVM tests, 148 Android-host tests, 16 Kotlin/Native tests and 62 sample unit tests.
- 44 instrumented tests (18 library, 26 sample) on phone and tablet API 29 emulators gate the
  release.
- Isolated publication verification; JVM and minified Android consumers passed against both the
  isolated repository and JitPack.

Migration from 2.4.0: callbacks and predicates take epoch days, `YearMonth` becomes
`GregorianYearMonth`, `HijrahDate` becomes `HijriDate`, `JalaliCalendar` becomes
`SolarHijriDate`, and `Locale` parameters are removed. See ADR 0006 and the README migration
section.

Known limitation: the iOS klibs are ABI-checked and published, but no iOS app or simulator test
was run in this environment; that requires macOS with Xcode.
